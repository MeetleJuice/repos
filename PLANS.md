# 0.26 planning reliability campaign

User authorization covers research, implementation, verification and publication. Existing projects, approved plans, public API defaults, source checkpoints and frozen acceptance checks are preserved.

## Phase A — evidence and failure baseline
Scope: every tracked file's byte/hash inventory, deep pipeline audit, independent read-only model/harness/local research, uploaded timeout/schema-failure reproduction.
Non-goals: treating an automated inventory as a manual semantic review, unverified benchmark rankings, live billed model/GPU experiments.
Acceptance: dated primary-source registers and five-domain synthesis with verified/inferred/untested claims; frozen new regression input and unchanged historical datasets.

## Phase B — achievable planning
Scope: correct schema-complete examples; optional guided outline plus task batches; staged native Ollama schemas; resumable unapproved drafts; final full-proposal review before approval.
Non-goals: lowering the 8192 planner floor, silently dropping requirements, approving partial outlines, changing legacy loaded plans, default extra cloud calls.
Acceptance: both prompt examples pass the real approval reviewer; guided batches obey version-1 scope/dependencies, preserve outline checks, stop on bad batches, resume only for matching request identity, and cannot bypass final review.

## Phase C — diagnosis and execution integrity
Scope: per-attempt sanitized findings/digests, explicit timeout/connection classification, optional 300/600-second local planning allowance, active-task scope on static repairs, preservation of fallback options.
Non-goals: claiming a socket timeout is a hard job deadline or guessing a GPU/loading cause; widening active-task repair scope.
Acceptance: uploaded-style timeout plus schema failures retain distinct reasons; out-of-task repairs are rejected before writes; unrelated model edits preserve fallback options.

## Phase D — usable delivery and release
Scope: one visible guided-planning action, draft progress, actionable failure panel, route clarity, research/limits documentation, versioned ZIP and updater publication.
Non-goals: agent-framework migration, universal app completion, automatic installation or model promotion.
Acceptance: actual browser flows cover guided planning through approval/build/real tests/export, failure explanations, stop/resume and settings preservation; full checkout/extracted tests, strict typing and all browser checks pass; updater validates published bytes.

The next measured target is a valid Loot Locker proposal on the user's real Windows/Ollama configuration. Fixture/controller results alone do not satisfy that hardware/model target. Paid live comparison requires an explicitly selected provider/model budget.

# 0.25 local harness update (historical)

## Phase 1 — audit and research
Scope: provider adapters, routing, capabilities, task execution, model/workflow/update controls and release packaging. Record primary-source provenance in docs/research/local-harness-sources-0.25.0.json.
Non-goals: framework migration, adding cloud providers, live billed experiments.
Acceptance: architecture and phased decisions recorded before implementation; regression input frozen.

## Phase 2 — local runtime support
Scope: loopback-only OpenAI-compatible endpoint (LM Studio or llama.cpp), optional private runtime key, model discovery, explicit persisted routes, consent and status labels.
Non-goals: installing runtimes/models, remote gateways, silently replacing existing routes.
Acceptance: real local HTTP fixtures exercise discovery and inference; local-only routes require no cloud consent; remote endpoints are refused.

## Phase 3 — bounded task execution
Scope: deterministic finish gate rereading the approved task/checkpoint/source, repeated identical-call detection, optional local token streaming with cooperative cancellation and bounded previews.
Non-goals: additional model reviewers, semantic correctness inferred from static checks, unrestricted shell tools.
Acceptance: changed-plan, repeated-call, cancelled-stream and missing-terminator regressions fail safely; saved candidates remain resumable; frozen acceptance checks stay unchanged.

## Phase 4 — usability and release
Scope: discoverable model controls, quiet live response display, progressive disclosure, reduced motion, structured update-ready event and dismissible banner, versioned archive.
Non-goals: automatic installation, cloud response streaming, desktop notification permission prompts.
Acceptance: actual browser flows cover model selection, preserved approval, live progress and update banner; full checkout/extracted tests and strict type checks pass before publication; updater validates the published archive.

Each phase is developer-controlled. This file does not authorize a generated app or model to modify Foundry or bypass project approval.
