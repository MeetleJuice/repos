# 0.18.0 — Five-category workflow overview

After update/restart, open an existing project and expand **Your project from idea to delivery** beneath Next Step. The five cards cover models, planning/approval, generation/recovery, verification, and workspace/delivery. Open buttons navigate to existing controls and do not approve, generate, execute or export automatically. Technical details are optional disclosures.

- **Setup:** fresh browsers restore server-persisted automatic model routes without inference. Existing explicit browser choices win. Cloud/execution consent is still required. No inference quota is inferred from configuration.
- **Planning:** inspect declared feature/task/HTTP/browser/manual mappings and advisory references to protected documents. Mapping is a plan claim, not implementation evidence; plans and frozen checks are not rewritten.
- **Generation:** newly saved tasks have exact source-change receipts. Older tasks retain their saved progress without fabricated receipts. A task with unchanged source is disclosed; static pass does not verify behavior. Restored checkpoints do not display future-task receipts as current saved work.
- **Verification:** current automated evidence and manual passed/failed/pending counts come from the same source-bound evaluator used by exports. Stale observations are pending, not current passes. Opening the overview runs no generated code or model request.
- **Delivery:** app ZIPs include **.foundry/DELIVERY.md**, a readable status/launch/next-step guide, plus the existing report/history. The metadata guide is not written into app source and is excluded from its manifest. Existing source files and report schema remain compatible; new report fields are optional additions.

The handoff guide explains that browser localStorage belongs to its browser and origin, including port. Use an app's own export feature when available before changing browser/port. Server databases stay in their app folder. Keep the previous working folder until the new output is tested.

No new provider/dependency, paid diagnostic probes, automatic execution, hidden truncation, approval changes or reduced acceptance requirements. Existing model panel, backup/update safeguards, repair limits, private credentials, projects and ZIP contents are retained; the ZIP adds only its export metadata guide. Project files tab shows source, while .foundry/DELIVERY.md exists only in the download.

Full audit: research/five-category-audit-v1.md. Controlled validation: research/five-category-results-v1.json. Model ranking/quotas, optional runtime availability, finite context/source budgets and native Windows behavior remain real limitations. Tests here use fixture providers, not the user's real keys.

Release validation: the final extracted ZIP passed 307 automated tests and six Chromium workflows. Strict type checks passed for 18 modules. All frozen fixture hashes remain intact. The final artifact is compared with the tested extraction; only validation documents may differ. Publication verifies downloaded bytes, checksum and updater extraction.
