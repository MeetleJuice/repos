# Harness source audit for Idea Foundry v0.26

Accessed 2026-10-20. Read-only source/documentation comparison; no model calls, benchmark execution, installs, repository edits, or paid services. Source snapshots and all generated artifacts are under this research directory.

## Finding

The inspected open implementations use product-owned control loops with explicit boundaries around tools, context and persistence. That supports keeping Foundry’s small bounded controller inspectable; it does not prove custom code is always better, or authenticate the supplied eleven-harness claim. No framework dependency is justified by this audit alone.

**Claim disposition: unverified as stated.** Six selected products are not a census of eleven production systems; Claude Code’s core is unavailable, and mini-SWE-agent labels its package Alpha in the inspected manifest. No original eleven-product list, method, definition of “framework,” production criterion, authors or report URL was established. The narrower observed pattern is custom principal control in five accessible core implementations, without an observed LangChain/LangGraph/CrewAI/AutoGen-owned coding loop in the inspected core files/manifests. This is not a complete transitive dependency audit.

A literal “no general-purpose framework anywhere” claim is already too broad: Aider’s optional help feature imports LlamaIndex VectorStoreIndex, and its help requirements name a LlamaIndex embedding package. This is documentation retrieval, not ownership of Aider’s coding loop. OpenHands also supplies its own reusable SDK; counting that as “a framework” changes the assertion. LiteLLM/model SDKs, Pydantic, MCP and A2A dependencies have different roles from orchestration frameworks.

## Practical guidance for Foundry

1. Keep the approved-plan/task/source state machine authoritative. Separate model requests, candidate edits, accepted source, check execution and manual acceptance. A model’s completion sentinel or final answer is not a verification oracle.
2. Reuse typed internal boundaries for routing, context assembly, atomic edit validation, execution consent and evidence receipts. A small protocol/interface may help testing; a new agent framework needs a concrete missing capability and measured maintenance benefit first.
3. Preserve sequential scoped tasks as the default. Parallel research is different from simultaneous writes. Any future agent fan-out needs shared request budgets, source ownership, cancellation and evidence reconciliation; upstream subagent support does not establish Foundry needs it.
4. Keep context selection explicit and bounded, retain complete-file values for included files, disclose omissions and source identity, and keep the frozen full-context replay path lossless. Upstream lossy summaries do not override Foundry’s existing serialization/data contract.
5. Keep memory as provenance-bearing project/task records and optional reviewed notes. Treat recalled instructions as context, not permission or verified source. Do not add vector storage or self-modifying promotion on this evidence.
6. Retain independent verification and separate local/cloud execution consent. Do not copy unrestricted Bash or yolo modes into a novice-facing bounded app generator. Expose source fingerprints, actual attempts, retained/cumulative history and unknown costs honestly.
7. Prefer a small falsifiable experiment: paired fixed fixtures and one bounded change at a time; record request/output size, actual calls, repair outcomes and independent behavior. Promote only after the approved measurement gate, not based on competitor architecture.

## Benchmark and causality limits

Same model name in two harness leaderboards does not isolate a harness effect. Hold exact model revision/provider, sampling/reasoning/output limits, prompt/tool contracts, task split/commit, environment/dependencies, evaluator, run budget, retries, filtering and time window constant. Record all attempts, failed transports, spend and unknown usage; pair task outcomes and publish uncertainty. Tools, retrieval, prompt formatting and evaluation contamination can all change results.

A cross-harness controlled study can estimate an effect under its specific conditions. It cannot attribute that effect to “no framework” unless framework choice itself is isolated while preserving behavior and budgets. Upstream marketing/benchmark figures are not Foundry completion/repair measurements. This audit ran no inference and claims no performance improvement.

## Access, provenance and limits

Native read-only Git HTTPS access succeeded for seven repositories (six products; OpenHands frontend plus backend SDK), each shallow clone pinned to its retrieved SHA. GitHub API and seven official Claude documentation URLs failed through the proxy with tunnel HTTP 403. We used official Git-hosted README/changelog/plugin material for Claude instead; its unavailable core internals remain unknown. No failed URL is cited as read.

The current OpenHands/OpenHands checkout is Agent Canvas. Its architecture explicitly delegates execution to software-agent-sdk, which was separately retrieved and pinned. Findings therefore describe these snapshots, not every historical OpenHands release. Branch HEAD is not a release pin or proof of deployed production state. Source trees were inspected, never executed.

Machine-readable files: `source-register.json` (57 file hashes, pinned URLs, repository SHA/date/access register); `seven-subsystems.json` (42 evidence cells); `web-access.json` (blocked web requests). Source snapshots are in `sources/`.
