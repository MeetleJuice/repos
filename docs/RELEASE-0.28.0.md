# v0.28.0 — builder-sized delivery

Update through **Update → Check for updates → Install & restart**. Keep the Foundry terminal open. Start with `Start-Foundry.bat` if managed installation is unavailable. Projects, private `.env`, saved routes and approvals stay in place.

## First test

1. Create a fresh small project. Paste a bounded idea such as a movie watchlist with add/list/watched/delete and SQLite persistence, standard library only.
2. Click **Plan for my builder →**. This uses outline + task batches and displays the builder's file/feature bounds. More requests can incur cloud charges; ordinary consent still applies.
3. Review the complete proposal: setup before dependent behavior, small file lists, explicit dependencies, meaningful acceptance and manual UI checks. Approve when it matches your intent.
4. Open **Dashboard ↗ → Observe workspace**, select this project and leave it beside Foundry. Recorded source rejection now appears separately from a model's JSON response.
5. Generate. A syntax/scope failure can receive one same-model scoped correction. Rejected source is not saved. Requests can still time out, hit quota or exhaust eligible models; the journal retains why.
6. Review the files, select your intended runtime and explicitly approve execution. Run **Build, test & repair**. Automated pass and manual acceptance remain distinct.
7. Download/run the generated app, perform every manual check and save actual results. Keep the journal/export if anything fails.

## Models

Open **Models → Model limits · published, installed and configured**. Connection checks read at most twelve installed model metadata records per refresh, without generation. Authenticated cloud catalogue checks can add published limits. Unknown output ceilings/minima remain unknown; displayed configured/default budgets are not model specifications or remaining quota.

Current saved settings are preserved. If you deliberately apply automatic local setup again, the new builder default is 16K context / 4K output, while planning retains its larger floor. This is not a measured GPU-fit recommendation. Embedding models remain excluded from app generation.

## Existing projects

Approved plans are not changed. A missing setup file or too-wide task in an approved plan needs a reviewed revision/new project; the builder cannot silently widen scope. Legacy histories and frozen checks remain loadable. Unapproved guided drafts bind to their full request identity; the new builder profile can cause an older draft to restart rather than mix incompatible planning inputs.
